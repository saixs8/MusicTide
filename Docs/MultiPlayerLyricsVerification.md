# 多播放器歌词适配 v0.9.7

## 获取与同步

SMTC 负责歌名、歌手、播放状态和播放时间，不负责歌词正文。酷狗保留原有 KRC 缓存及真实时间路径；QQ、网易云、汽水等进入独立分支，按以下方式获取：

1. 系统媒体会话提供的真实时间。
2. 绑定当前播放器与当前歌曲的 UI Automation 时间控件（组合时间或两个独立时间标签）；前台窗口底部 OCR 作为回退。
3. 本机已缓存的匹配时间轴、用户明文 LRC、常见播放器明文 LRC 目录。
4. 网易云歌词源、LRCLIB：严格匹配歌名／歌手，已知时长时允许最多 4 秒误差，避免翻唱和现场版本错配。仅有歌名且无歌手、无时长时，不自动选一个版本。
5. 同一播放器桌面歌词窗口的文字／可见像素 OCR；唯一歌词句可给估算时间校时，重复副歌没有独立进度时不猜位置。

请求及窗口扫描分别在后台任务运行。歌曲键改变时取消旧请求，丢弃旧时间轴；已返回的窗口结果必须同时符合播放器、歌曲身份及两秒有效期。多个播放器同时运行时优先选择正在播放的媒体会话。原始歌词只缓存到本机，联网歌词源请求的是歌名和歌手；本机 AI 不调用云端。

## 检查结果

- `dotnet run --project Tools/MultiPlayerVerification -c Release -- --network`：51 项通过。涵盖六种播放器别名、无关窗口排除、歌名身份、拆分时间标签、LRC 毫秒／偏移／重复时间／空白段、版本匹配、中途对齐、暂停、前后跳转、切歌和旧异步结果隔离。
- QQMusic、CloudMusic、SodaMusic 测试进程以 WinForms 窗口暴露真实时间与桌面歌词控件，实际跨进程读取。**这些是测试窗口，不是厂商客户端**；用于检查本程序的读取路径和时间／歌曲隔离。
- 联网实际取得《孤勇者》（陈奕迅）78 行歌词，时长 256 秒，源为网易云；随后本机缓存重用通过。网易云搜索和 LRCLIB 搜索 HTTP 路径实际返回过 JSON；LRCLIB 完整同步分支未以厂商客户端现场验证。
- `Tools/LyricVerification` 原有 28 项回归检查通过：酷狗、时钟插值、暂停、中途对齐、旧歌时间隔离等。
- 酷狗现场：54 行歌词，真实进度从 20.35 秒推进到 22.31 秒；音频包 108→613，量能单步变化最高 0.4007。没有改变播放器播放状态。

## 实际客户端范围

本机只运行酷狗。QQ／网易云／汽水官方客户端各版本仍需实际播放检查，尤其不同版本是否发布 SMTC 时间、是否暴露无障碍文字、桌面歌词窗口类名及自绘行为。不能将模拟窗口测试描述成三款客户端已全部现场通过。

缺少匹配歌词时尝试开启桌面歌词；缺少真实进度时状态显示“估算进度／等待校时”。没有时间轴和桌面歌词时无法从系统音频直接转写。本次没有引入语音转写模型，也没有解密 QQ QRC 等专有缓存。

## 研究依据

- [qishui-obs-lyrics](https://github.com/PuDood/qishui-obs-lyrics)：研究汽水的 Soda／Qishui／Luna 进程身份、SMTC 与 UI Automation 时间获取思路。本程序使用独立实现，没有复制其重启歌曲或自动跳过歌曲逻辑。
- [ESLyric-LyricsSource](https://github.com/Robotxm/ESLyric-LyricsSource)：研究播放器识别与歌词供应方分离，QQ 接口实测旧搜索端点 HTTP 500、桌面搜索返回空，因此未把它作为本次可靠依赖。
- [LRCLIB 文档](https://lrclib.net/docs)：查询带时间轴的歌词并按曲名、歌手、时长校验。
